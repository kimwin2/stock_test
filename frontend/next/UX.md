# UX 재설계 — 왜 갈아엎는가

> `frontend/next/` 는 **기존 화면(`frontend/`)을 건드리지 않는 별도 시안**이다.
> 같은 데이터(S3 `dashboard_data.json` / `flow_dashboard.json`)를 읽고,
> 같은 차트 API를 쓴다. 기존 화면은 그대로 살아 있다.

---

## 0. 먼저 — 이 제품이 답하는 질문

기능 목록에서 출발하면 카드가 계속 늘어난다. 질문에서 출발하면 화면이 정해진다.
트레이더가 하루에 실제로 던지는 질문은 여섯 개고, 순서가 있다.

| # | 질문 | 답하는 데이터 |
|---|---|---|
| Q1 | 오늘 사도 되는 장인가 | 공포·탐욕(F&G), 쏠림(장 난이도), 현금비중 권고 |
| Q2 | 어디가 강한가 | 주도 업종 (ETF RS · 수급 강도 · 거래대금 쏠림) |
| Q3 | 그래서 뭘 볼까 | 매수 후보 = 빈집 ∩ 주도섹터 ∩ 추세생존 |
| Q4 | 왜 이게 뽑혔나 | 포착 경로, 필터 통계, ETF 편입비중 |
| Q5 | 갖고 있는 건 괜찮나 | 이탈 신호 (고점 대비 낙폭 · 10일선 이탈) |
| Q6 | 오늘 뭐가 왜 올랐나 | 급등 테마 + 뉴스 근거 |

**Q3 가 이 제품의 본체다.** Q1·Q2 는 Q3 를 믿을 수 있게 만드는 전제고,
Q4 는 Q3 를 근거로 바꾸는 장치다. 화면의 무게도 그 순서여야 한다.

## 1. 언제 여는가

| 시각 | 상황 | 필요한 답 |
|---|---|---|
| 08:00~08:50 | 장 전, 오늘 계획 | Q1 → Q2 → Q3 |
| 09:00~15:20 | 장중 | Q6, 관심종목 점검 |
| 15:30~20:00 | 장 후, 종가베팅 확정 | Q3 → Q4 → Q5 |

세 시점 모두 **한 손 · 세로 · 짧은 시간**이다. 데스크톱에서 오래 들여다보는
화면이 아니다. 그래서 모바일이 기준이고, 데스크톱은 그 확장이다.

---

## 2. 기존 화면의 문제 (상용 제품 기준으로)

고친 근거를 남긴다. 취향이 아니라 이유가 있어야 다음 사람이 되돌리지 않는다.

### 2-1. 읽을 수가 없다

`html { font-size: 14px }` 위에 본문이 `0.74~0.85rem`. 실제 렌더 크기가
**10.4~11.9px** 다. iOS·Android 기본 본문은 16~17px, 금융앱 보조 텍스트도
13px 아래로 잘 안 내려간다. 정보가 아무리 좋아도 읽히지 않으면 없는 것이다.

→ 루트 16px, 본문 15px, 보조 13px, **캡션 하한 12px**. 그 아래는 안 쓴다.

### 2-2. 주인공이 없다

카드 12개가 전부 비슷한 크기·비슷한 굵기로 쌓여 있다. 시선이 어디서 시작해
어디서 끝나는지 화면이 말해주지 않으니, 사용자가 매번 스스로 우선순위를
정해야 한다. 그 피로가 "중구난방" 이라는 말의 실체다.

→ **한 화면에 결론은 하나.** 홈은 "오늘 볼 종목 N개" 라는 답 하나를 크게 놓고,
나머지는 그 답을 뒷받침하는 순서로 내려간다.

### 2-3. 누르면 아무 일도 안 나는 것들

- 헤더의 뉴스·히스토리·캘린더 아이콘 3개 — 이벤트 핸들러가 없다
- 하단 뉴스 티커 — 자동으로 흘러가서 읽을 수 없고, 멈출 수도 없다

죽은 버튼은 신뢰를 깎는다. 한 번 눌러보고 반응이 없으면 나머지 버튼도
의심하게 된다. → **동작하지 않는 컨트롤은 놓지 않는다.**

### 2-4. 탭이 위에 있다

세로로 긴 폰에서 상단 탭은 엄지가 안 닿는다. 게다가 헤더가
로고+시각+아이콘3+검색바+탭 5층이라 첫 화면의 40%를 헤더가 먹는다.

→ **하단 탭바.** 검색은 상시 바 대신 아이콘 하나 → 전체화면 검색.

### 2-5. 용어가 설명 없이 나온다

빈집 · 오실레이터 · RS · 쏠림 · TI · 백분위. 처음 보는 사람은 여기서 멈춘다.
지금도 `whatIs()` 로 일부 설명이 붙지만 카드마다 문장이 길게 깔려 밀도를 해친다.

→ 용어 옆 **ⓘ 한 글자**. 누르면 바텀시트로 정의 + 왜 보는지 + 어떻게 읽는지.
설명은 필요한 사람만 꺼내 본다.

### 2-6. 터치 타겟이 작다

`<summary>` 접기 줄, 칩, 필터가 대부분 30px 대. 손가락 최소 권장은 44~48px.

### 2-7. 색이 경쟁한다

브랜드 브론즈(#B07A1C)가 등락 빨강·파랑과 같은 채도로 붙어 있어서, 색이
"의미" 인지 "장식" 인지 구분이 안 된다.

→ **색은 등락에만 의미를 준다.** 빨강=상승, 파랑=하락, 그 외는 전부 무채색
계열. 브랜드색은 로고와 활성 탭 한 곳에만.

### 2-8. 로딩이 빈 화면 + 스피너

`flow_dashboard.json` 은 1.9MB다. 느린 회선에서 몇 초간 스피너만 돈다.

→ **스켈레톤.** 올 자리를 미리 보여주면 체감 대기가 절반이 된다.

### 2-9. 다크모드가 없다

장 마감 후·새벽에 보는 앱이다. 시스템 다크에서 흰 화면이 그대로 뜬다.

## 3. 새 구조

```
┌─ 상단: 날짜 · 갱신시각 · 검색 · 테마전환 (48px, 얇게)
│
├─ [탭] 오늘
│    ├ 히어로      오늘 한 줄 + "오늘 볼 종목 N" (가장 큰 활자)
│    ├ 장 상태     심리 / 난이도 / 현금  — 3칸, 각 칸 탭 → 설명 시트
│    ├ 주도 업종   칩 5개 + 근거(ETF RS·수급·거래대금) — 탭 → 그 섹터 종목
│    ├ 오늘 볼 종목 상위 5 + [전체 N개 보기]
│    ├ 어떻게 좁혔나 깔때기 (접힘)
│    ├ 오늘의 재료  테마 3 + 수급 겹침 표시
│    ├ 점검        이탈 신호 N건 (접힘)
│    └ 어제와 변화  진입/이탈 (변화 없으면 렌더 안 함)
│
├─ [탭] 종목
│    ├ 세그먼트: 빈집 후보 / 거래대금 상위 / 이탈 신호
│    ├ 정렬: 순위 · 빈집 깊이 · 5일 등락
│    └ 행 탭 → 종목 상세 시트
│
├─ [탭] 테마
│    ├ 오늘의 지도 (트리맵)
│    └ 테마 카드 (뉴스 근거 + 종목별 등락)
│
└─ [탭] 관심
     └ 저장 종목 (localStorage) · 비어 있으면 담는 법 안내
```

### 3-1. 홈 히어로가 답하는 것

기존 홈은 반원 게이지가 주인공이었는데, 그 게이지는 **F&G 하나**만 인코딩한다.
Q1의 일부일 뿐이라 첫 화면의 자리값에 못 미친다.

→ 히어로는 **오늘의 결론**을 놓는다: 한 줄 헤드라인 + `오늘 볼 종목 N개`.
F&G 는 바로 아래 3칸 중 하나로 내려간다. "지금 시장이 어디쯤"은 3칸이 답한다.

### 3-2. 종목 상세는 페이지가 아니라 시트

후보를 훑다가 하나를 열고, 아니면 닫고 다음으로 넘어간다. 페이지 전환이면
매번 뒤로가기 → 스크롤 위치 복원 문제가 생긴다. **바텀시트**가 이 흐름에 맞다.

시트 내용 순서 = 사용자가 묻는 순서:
1. 얼마인가 (현재가·등락·업종)
2. 어떻게 생겼나 (일봉 + 수급 오실레이터)
3. **왜 뽑혔나** (포착 경로: 주도 근거 → 섹터 → ETF 편입 → 종목 상태)
4. 수급이 언제 돌았나 (10일 히트맵)
5. 숫자 (거래대금 배율 · 외인지분 · 고가대비 · MA)
6. [차트 크게] → 분/일/주/월 전체화면

### 3-3. 관심 탭을 새로 두는 이유

지금은 "오늘 뽑힌 20개" 를 매일 새로 읽어야 한다. 어제 본 종목을 다시 찾으려면
방법이 없다. 관심 목록은 서버 없이 `localStorage` 로 되고, 매일 여는 이유를 만든다.
저장된 종목은 오늘 후보에 다시 들었는지(★재진입) 표시한다.

## 4. 무엇을 버리는가

| 버리는 것 | 이유 |
|---|---|
| 헤더 아이콘 3개 | 동작 안 함 |
| 하단 뉴스 티커 | 흘러가서 못 읽음 · 세로 공간 상시 점유 |
| 상시 검색바 | 첫 화면 세로 공간을 매일 먹는데 사용 빈도는 낮음 |
| STEP 1·2·3 번호 | 위에서 아래 순서가 이미 순서를 말한다 |
| 브론즈 브랜드색 | 등락색과 경쟁 |
| 카드마다 긴 설명 문단 | ⓘ 시트로 옮김 |
| 정밀분석 `<details>` 뭉치 | '종목' 탭 세그먼트로 승격 |

## 5. 무엇을 지키는가

기존 코드 주석에 사고 기록이 많이 남아 있다. **되돌리면 안 되는 것들**:

- **빈집 판정은 부호가 아니라 감속** — `osc < 0`. UI 문구도 "외인·기관이
  빠져나간 자리" 로 통일한다.
- **게이지 단계는 zone 우선, 백분위는 세부** — 카드와 시트가 다른 말을 하면 안 됨
- **`oscPercentile` 과 `vacancyPercentile` 은 다른 물건** — 화면엔 osc 쪽만
- **테마 탭에 수급 언어를 흘리지 않는다** — 빈집 판정은 오늘·종목 탭에서만
- **이평선 색은 어느 화면에서나 같다** (5일선/20일선)
- **상승 빨강 · 하락 파랑** (국내 관례)
- **섹터 상한에 걸린 종목은 숨기지 않는다** — 접어두되 개수는 드러낸다
- **필터 통계(몇 개 → 몇 개)를 보여준다** — 근거 없는 목록은 신뢰를 못 얻음

## 6. 타이포·간격·터치 규칙

| 항목 | 값 |
|---|---|
| 루트 | 16px |
| 본문 | 15px / 1.55 |
| 강조 숫자 | 28~44px, tabular-nums |
| 보조 | 13px |
| 캡션 하한 | 12px |
| 터치 타겟 | 최소 48px |
| 카드 여백 | 16px |
| 화면 좌우 | 16px (safe-area 추가) |
| 모션 | 180~220ms, `prefers-reduced-motion` 존중 |

## 7. 검증 체크리스트

- [ ] 폭 320 / 375 / 430 / 768 / 1024 에서 가로 스크롤 없음
- [ ] 모든 버튼·행이 실제 동작 (죽은 컨트롤 0)
- [ ] 라이트·다크 양쪽에서 대비 확보
- [ ] 데이터 없음 / 로딩 / 에러 상태가 각 화면마다 존재
- [ ] 전문 용어에 전부 ⓘ 연결
- [ ] 키보드 Esc 로 시트·모달 닫힘, 포커스 복원
- [ ] 기존 `frontend/` 는 단 한 글자도 바뀌지 않음
